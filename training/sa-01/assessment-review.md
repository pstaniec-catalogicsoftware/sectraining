# SA 01 Assessment Review

Draft 0.2.0. Five equally weighted questions; draft pass threshold 80 percent, configurable by the programme owner. Practice decisions are unscored.

## Q01

An email looks like it's from your manager and asks you to send a sensitive document by email instead of using the usual sharing workspace. What should you do first?

- Reply to the message and ask if it is genuine.
- Check with your manager using contact details you already trust, before sharing anything.
- Send the document because the manager's name is correct.

**Correct:** Check with your manager using contact details you already trust, before sharing anything.

A familiar name doesn't confirm who sent the message. Check the request independently before changing the usual sharing process.

Objective: Recognise process bypass and verify before acting.

## Q02

The email includes a phone number to call if you have questions. Which route would give you an independent check?

- The number in the message.
- A number in the attached instructions.
- The existing entry in {{directory.label}}, opened separately from the message.

**Correct:** The existing entry in {{directory.label}}, opened separately from the message.

The number in the email or attachment comes from the same unverified source. Use an existing contact in your company directory.

Objective: Choose an independent contact route.

## Q03

You're not sure whether an email is malicious. Do you need proof before reporting it?

- Yes. Investigate until you can prove it.
- No. Report the concern through {{reporting.primary.label}}, using the approved fallback if needed.
- Wait until another employee confirms they received it too.

**Correct:** No. Report the concern through {{reporting.primary.label}}, using the approved fallback if needed.

You can raise a concern without proving there's been an attack. Use the company process so the team can look into it.

Objective: Report concerns under uncertainty.

## Q04

You've checked with your manager independently, and the urgent request is genuine. What should you do next?

- Use {{sharing.label}} with the normal recipient, access, and permission checks.
- Use any convenient sharing method because the request is genuine.
- Refuse because urgent requests should never be acted on.

**Correct:** Use {{sharing.label}} with the normal recipient, access, and permission checks.

Go ahead using the approved sharing process, including the usual access and permission checks.

Objective: Proceed safely after legitimate verification.

## Q05

A colleague messages you in chat asking for a customer export through an unusual route. They say there's no time for a call. What should you do?

- Send it because an internal chat identity is enough.
- Send it now and verify after the deadline.
- Check with the colleague independently before sharing, and report anything concerning through the company process.

**Correct:** Check with the colleague independently before sharing, and report anything concerning through the company process.

Use the same approach in chat as in email. A familiar name and a deadline don't remove the need to check a sensitive request.

Objective: Apply independent verification to collaboration chat.
